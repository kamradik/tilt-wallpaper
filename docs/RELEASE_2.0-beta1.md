# Solo 2.0-beta1

Развитие существующего приложения: тот же пакет `dev.solotilt.personal`, та же подпись, сохранённая фотография и страница Kamradik. Это **бета**, не подтверждённое исправление POCO.

## Что изменилось

- Пять режимов в одном EGL/OpenGL ES 3 renderer: Classic Tilt, Depth Parallax, Dynamic Light, Liquid Glass, Focus Rack. Два параметра каждого режима сохраняются отдельно.
- Датчики работают на отдельном потоке: game rotation vector → rotation vector → gravity → accelerometer, включая отказ регистрации. Latest-value mailbox объединяет частые события, Choreographer согласует кадры с дисплеем. Смена refresh rate пересчитывает частоту кадров.
- Переиспользуются массивы ориентации и проекции; uniform locations определяются при создании shader program. Декодирование фото и подготовка глубины вынесены из кадров. Gaussian mip pyramid создаётся после загрузки, а не заново при движении.
- Auto / Battery / Balanced / High задают предел внутреннего разрешения. Battery и энергосбережение целятся в 30 кадров/с, остальные — до 60, с учётом частоты экрана. Нагрев снижает разрешение. Это целевые частоты, не измеренная производительность телефона.
- После затухания движения и touch-анимации отрисовка останавливается. Невидимые обои останавливают и датчики. При смене поверхности сохраняется декодированное фото.
- Новая панель Solo, миниатюры выбранного фото, мгновенный preview, системный выбор фотографии, настройки crop/zoom, нейтрального положения, чувствительности, Reduce Motion, русского/английского интерфейса.
- Debug APK показывает HUD и пишет `SoloPerf`: FPS, CPU submit, время swap, оценку пропущенных кадров, частоту датчика, возраст его данных, разрешение, sensor name и thermal status. Обычный APK HUD не включает.

## Честные ограничения

Автокарта глубины — **пространственно-яркостная эвристика**, а не нейросетевая оценка расстояния. На некоторых фотографиях глубина будет неверной. `DepthProvider` изолирован для замены лицензированной мобильной моделью; текущий результат кэшируется один раз. Для точного соответствия объектам импортируйте совпадающую с фото карту глубины: белое ближе, чёрное дальше. Depth и Focus используют одну GPU-карту.

Панели используют заранее уменьшенную фотографию как дешёвую подложку стекла. Это не динамическое считывание framebuffer; миниатюры тоже не запускают пять дополнительных renderer. Focus Rack использует Gaussian mip LOD, а не физическую симуляцию линзы. Касания обоев зависят от того, какие события передаёт launcher.

CPU submit / swap / sensor age не являются измерением GPU duration или sensor-to-photon. Пропуски оцениваются по интервалам Choreographer. На неподвижном телефоне низкий FPS нормален: idle rendering намеренно выключен. Для сравнения устройств нужен одинаковый сценарий непрерывного движения.

## Проверено на компьютере

- Полная компиляция Java 17 → D8 → APK; проверка подписи apksigner, обычная и debug сборки.
- FoldMath: нейтральная проекция, симметрия, ориентации, крайние углы, некорректные данные, переиспользуемые буферы.
- CoreChecks: повреждённые/будущие настройки, ограничения значений, сохранение пяти режимов, reset, конкурентная передача 100 003 sensor states.
- WebGL2/SwiftShader: фактические GLSL программы всех пяти режимов, 10 уровней двухпроходного Gaussian blur, реакция новых режимов на наклон, заполненность краёв и переход. Это проверка шейдеров, **не Android/GPU benchmark**.
- `javac -Xlint:all`: нет ошибок, три предупреждения deprecated API для совместимости Android 11+. Android Lint не запускался: локально установлен SDK build-tools, без Gradle/Android Lint distribution.
- Визуально просмотрен [результат GPU-проверок](effects-check.png).

На момент сборки `adb devices -l` пуст. Android UI, установка, launcher, screen off/on, процесс после убийства и реальные показатели POCO/AOSP **не проверены на устройстве**.

## Проверка на POCO C85 / HyperOS 3 / Android 16

1. Установить `Solo-2.0-beta1-debug.apk` поверх прежней версии. Подпись совпадает; удалять приложение не нужно. Debug APK заменяет обычный APK, оба имеют один пакет.
2. В Classic выбрать Auto; наклонять непрерывно 30 секунд. Сохранить HUD и `adb logcat -d -s SoloPerf SoloRenderer SoloDepth SoloImage`.
3. Повторить в Battery и Balanced, затем для остальных режимов с той же фотографией. Сравнивать CPU submit, swap, sensor age и missed, а не только FPS.
4. Проверить preview → системное окно → рабочий стол. Повторить блокировку/разблокировку 10 раз, уход в другое приложение, перезапуск процесса, смену фото и режима, импорт корректной/повреждённой карты.
5. Проверить энергосбережение и 10 минут движения для thermal throttling. Для tracing использовать Perfetto с FrameTimeline/sched/freq/gfx/view; лог не заменяет GPU trace.
6. Повторить на AOSP-устройстве/эмуляторе. Проверить большой системный шрифт, TalkBack, светлое/тёмное фото, длинное/широкое фото, отсутствие датчика, остановку музыки страницы автора.
7. После проверки установить обычный `Solo-2.0-beta1.apk`, чтобы убрать диагностический HUD.

## Воспроизведение проверок

```powershell
./build.ps1
./tests/check-core.ps1
# Node.js + Playwright; можно задать PLAYWRIGHT_MODULE абсолютным путём.
node tests/effects-check.cjs
./build.ps1 -DebugBuild
```

`check-core.ps1` скачивает проверяемый по SHA-256 JSON jar только для host-тестов. В приложение он не включается: Android предоставляет org.json. Build prerequisites описаны в README.
