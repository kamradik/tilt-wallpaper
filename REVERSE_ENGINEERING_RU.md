# Реверс-инжиниринг Solo Tilt для Android

Дата исследования: 19 сентября 2026. Целевой телефон пользователя: Samsung S23 Ultra, One UI 8.5.

**Примечание к публичному репозиторию:** документ описывает исходное локальное исследование. Упомянутые ниже `analysis/`, оригинальный APK, инвентаризация и декомпиляция сохранены только в локальном исследовательском комплекте и не публикуются здесь. Проверочное изображение перенесено в `docs/shader-check.png`. После исследования пользователь подтвердил работу обоев версии 1.0 на S23 Ultra; в 1.1 добавлена страница автора, для которой пока выполнены сборка и статическая проверка.

## Исходные данные и границы вывода

Исследованы предоставленное видео `video_2026-09-19_17-34-05.mp4` (35,08 с, 1194×2560), публичная страница https://solotilt.com/, её клиентский JavaScript и APK по ссылке https://solotilt.com/downloads/solo-tilt-android.apk, найденной в клиентском коде страницы. Текущая веб-версия и Android-версия имеют разные формулы эффекта; для Android выбран именно APK.

Слово «полный» здесь нельзя понимать как восстановление исходного проекта автора: обфускация уже уничтожила имена, комментарии и часть исходной структуры. Сохранены все 41 доступных DEX-класса, методы, инструкции, манифест, строковые ресурсы и три GLSL-шейдера. Серверный код, история сборок и исходные проектные файлы из APK не восстанавливаются. Динамическое исследование на телефоне не проводилось.

Декомпилятор Androguard выдаёт псевдо-Java с ошибочными типами, синтаксисом конструкторов и числовыми представлениями float. Эти файлы не предназначены для компиляции. Для проверки спорных мест рядом сохранено DEX-дизассемблирование. Отдельное приложение написано читаемым Java-кодом, а не собирается из псевдо-Java.

## Датчики

Приоритет — `TYPE_GRAVITY` (9), резерв — акселерометр (1). Период запроса 33 333 мкс. Для акселерометра применяется экспоненциальный низкочастотный фильтр с постоянной времени около 0,18 с. Оси преобразуются с учётом вращения дисплея 0/90/180/270°.

После преобразования осей:

```text
r = hypot(gx, gy)
theta = degrees(atan2(r, gz))
x = gx * theta / r
y = gy * theta / r
```

Положение экраном вверх даёт x=y=0. Наклон выше 120,00001° сбрасывает эффект в нейтральное положение. Некорректные измерения и вектор с длиной менее 0,5 игнорируются. Небольшие изменения менее 0,05° не планируют новый кадр.

На потоке рендера применяется сглаживание:

```text
alpha = 1 - exp(-dt_ms / 70)
current += (target - current) * alpha
```

При остатке менее 0,02° значение фиксируется на цели. При отсутствии движения рендер перестаёт планировать кадры. Целевой период кадра оригинала — 33 мс, примерно 30 FPS, даже на экране 120 Гц.

## Оптическая модель

Это имитация неподвижной плоскости изображения за наклоняющимся стеклом. Нейросеть, depth map, сегментация объекта и отдельные 3D-слои не используются. Поэтому эффект работает с любой картинкой.

Размер дисплея в миллиметрах выводится из `sqrt(xdpi * ydpi) / 25.4`; если dpi невалиден или вне 100…1000, используется `160 * density`. Точность Android DisplayMetrics влияет на визуальный результат.

Углы x/y ограничиваются диапазоном ±120° и умножаются на 0,75. Геометрическая проекция зависит от горизонтального угла; вертикальная составляющая дополнительно меняет размытие. Это существенное отличие от произвольного 3D-вращения по двум осям.

Пусть W — ширина дисплея в мм, A — width/height, s — знак x, t=abs(x) в радианах после масштабирования, c=cos(t), q=sin(t). Для координаты пикселя `p=((uv-0.5)*(1,1/A),1)` используются:

```text
projectionX = (c, 0, s * 0.5 * (c-1))
projectionY = (0, 1, 0)
gap         = (s*q*W, 0, 0.5*q*W)
projectionZ = (-gap.x/320, 0, 1-gap.z/320)
hit = (dot(projectionX,p), dot(projectionY,p)) / dot(projectionZ,p)
imageUV = hit*(1,A)+0.5
```

320 мм — фиксированная дистанция наблюдателя. Отрицательная глубина становится чёрной. Центрированное cover-масштабирование сохраняет пропорции фото, но может обрезать края.

Огибающая размытия `gain * sin(maxAngle * clamp((abs(angle)-start)/(end-start),0,1))`:

| Ось | Gain | Start | End | MaxAngle |
|---|---:|---:|---:|---:|
| X | 0,68 | 14° | 100° | 90° |
| Y | 0,28 | 25° | 100° | 25° |

Огибающая умножается на W. Знаки задают направление размытия, а положительный сдвиг в `blurGap.z` удерживает минимальный зазор у края стекла.

В пиксельном шейдере:

```text
gapMm = max(0, dot(blurGap,p))
radiusMm = 0.12 * gapMm
sigma = radiusMm / screenWidthMm * coverScale.x * imageWidth
lod = max(0, log2(max(sigma,1)))
attenuation = max(1 - 0.09*0.12*max(0,dot(gap,p)), 0)
```

Чернота за пределами изображения смягчается `smoothstep` с радиусом, связанным с размитием. Для sigma меньше 2 смешиваются резкий уровень и первый размытый. Для большего sigma используется дробный mip-уровень.

## Gaussian-пирамида

Вершинный шейдер рисует полноэкранный quad из двух треугольников. При загрузке изображения сначала строятся стандартные mipmaps, затем по одному уровню за кадр выполняется separable Gaussian: горизонтальный проход во временную текстуру и вертикальный — в текущий mip-уровень изображения.

Веса: 0,2270270270 в центре; по 0,3162162162 на смещениях ±1,3846153846; по 0,0702702703 на ±3,2307692308. Билинейная выборка позволяет использовать пять выборок вместо девяти. Результат подготавливается после смены фото, а не заново на каждый пиксель каждого кадра.

Три шейдера в собственной сборке байт-в-байт совпадают с ресурсами исследованного APK. CPU-обвязка и UI написаны заново. Это не гарантирует идентичность всей картинки на другой версии программы или при других входах датчиков.

## Изображения и жизненный цикл

Оригинал декодирует изображение через ImageDecoder в software bitmap, ограничивает длинную сторону до 2048 px и приводит в sRGB. Импорт сохраняется атомарно как JPEG с качеством 95 в приватном `wallpaper.jpg`. Настройки `selected_source` и `image_revision` синхронизируют предпросмотр и WallpaperService. Есть 13 встроенных образцов.

Сервис выключает события касания и смещения страниц рабочего стола. Датчики работают только при наличии видимой поверхности. EGL и графические ресурсы принадлежат отдельному HandlerThread. При длительных медленных кадрах оригинал снижает лимит картинки до 1024 px, затем может перейти на неподвижную картинку. Есть попытка восстановления EGL при потере контекста.

В собственной версии фото импортируется через системный ACTION_OPEN_DOCUMENT и сохраняется атомарно в PNG; EXIF-ориентацию обрабатывает ImageDecoder. PNG выбран для исключения повторных JPEG-артефактов. Три образца нарисованы программно. Автоматическое снижение до 1024 px из оригинала не переносилось; при ошибке EGL предусмотрен статический fallback. UI и набор встроенных картинок отличаются от оригинала.

## Лицензия и сеть оригинала

Оригинал объявляет INTERNET, SET_WALLPAPER, READ_EXTERNAL_STORAGE до API 32 и MANAGE_EXTERNAL_STORAGE. Последние два разрешения связаны в том числе с попыткой чтения текущих системных обоев.

Клиентский код содержит POST-вызовы `https://solotilt.com/api/license/` для активации, проверки, деактивации и восстановления. Установлены таймауты 15 с и запрет автоматических редиректов. Состояние лицензии хранится в `license.enc` с AES-GCM; ключ — в Android Keystore. Идентификатор устройства получается хешированием имени пакета и Android ID.

При выборе импортированной картинки кнопка установки проверяет лицензию. Wallpaper-renderer также подменяет импорт встроенной картинкой при отсутствии активной лицензии. Это подтверждается `a.r` и `a.m0`, а не выводится только из наличия кнопки License. Серверные API не вызывались, лицензии не активировались, бинарник не патчился.

Собственное приложение не использует сервер оригинала и его состояние лицензии. Оно реализует локальный выбор и хранение пользовательской картинки самостоятельно.

## Проверка и оставшиеся ограничения

Проверенная сборка выполнена официальными Android build-tools 36, JDK 17 и SDK 36. Подпись новой сборки проверена по схеме v3; подпись оригинала — v2. Математические тесты охватывают полный диапазон углов. WebGL2 smoke test компилирует все три GLSL-программы и визуализирует четыре положения; его mipmaps упрощены и не подтверждают Android Gaussian-пайплайн.

На момент проверки `adb devices -l` не показывал устройств. Поэтому установки, открытия UI, реальной работы WallpaperService, импортов из Samsung-галереи, производительности и поведения блокировки на One UI 8.5 не проверяли. Для приёмки на телефоне нужно выбрать одну и ту же картинку в обеих программах, выставить одинаковую ориентацию и сравнить несколько одинаковых положений. Само видео не содержит телеметрию датчиков, поэтому восстановить побитно всю анимацию из него невозможно.

Готовый результат — собираемый проект и подписанный APK с восстановленной оптической моделью; не заявление о доказанном совпадении кадр-в-кадр или о восстановлении закрытого серверного кода.
